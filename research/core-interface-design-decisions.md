# Core C-interface — designer's adjudication

This memo records the main-thread designer's decisions over the research draft `core-c-interface-draft.md`. The draft is research input; this memo is the design authority for the upcoming contract PR. Where this memo is silent, the draft's proposal is adopted as written.

## Adopted architecture (confirmed by independent review)

1. **Naming and surface**: `mxq_` prefix, one public header `mxq.h`, ~52 functions in six groups. Adopted.
2. **Handle model**: exactly three opaque handles (`MxqCore` singleton-enforced, `MxqGame` session, `MxqBlob` immutable bytes); everything else sized POD value structs (`struct_size` first member), strings by value in fixed caps, booleans as `uint8_t`, enums with explicit `int32_t` values. Adopted — this yields blittable C# and `Sendable` Swift types with zero lifetime questions.
3. **Session model**: `MxqGame` is a game session composing the rules facade with the frozen per-game config; the pure rules facade is additionally exposed session-free (`mxq_rules_evaluate` / `mxq_rules_legal_moves`) over `(start_fen, moves[])` — never a bare FEN — which is exactly the fixture-harness and import-validation surface. Adopted; resolves draft gap G3 the right way.
4. **Session concurrency**: single-owner with concurrent-use *detection* (`MXQ_ERR_ARG_CONCURRENT_USE`), not internal serialization. With one main window and one active game, concurrent session access is a frontend bug; a mutex would order the race arbitrarily and hide it. Swift actor isolation enforces the same rule at compile time. Adopted.
5. **Search delivery**: one core-owned engine thread; completion callback on that thread at the faithful in-process substitute for Fairy-Stockfish's own `bestmove` point (after pool quiescence); `mxq_search_poll`/`mxq_search_wait` kept for deterministic tests and binding fallback. C12 rejection ladder (cancelled → stale → malformed → illegal) applied before delivery; stale rejection enforced both core-side and frontend-side. Adopted.
6. **Store calls**: synchronous, internally serialized on one connection, documented "never from the UI thread". Adopted.
7. **Commit boundary (draft gap G5)**: sessions are store-attached from birth (create/resume) or detached read-only (replay/import preview); attached mutations commit inside the call. This is the only faithful reading of game-data's "explicit commit after every accepted move; a committed move is the recovery boundary" — a separate frontend-issued save call would reopen the window that rule closes. Consequence accepted and made explicit: `mxq_game_apply_move`, `undo`, `claim_draw`, `resign` can block briefly and can return storage errors. Adopted.
8. **Error model**: `int32_t` status enum in 1000-blocks + optional `MxqError` out-param on every fallible function; no thread-local last-error (broken under Swift's cooperative pool and inside callbacks). Programming errors assert in debug, return codes in release, never mutate state. Adopted.
9. **Library observation**: return values + monotonic `library_revision`; no notification mechanism in the MVP. Adopted.
10. **Versioning**: sized structs + append-only enums + `MXQ_API_VERSION` check at init; source-compatibility promise within a major; four independent version axes (C API / archive / store schema / engine profile) reported by `mxq_core_version`. Adopted.
11. **Windows binding**: C# P/Invoke with `[LibraryImport]` + ClangSharp-generated declarations from the same header the Swift module map consumes; no C++/WinRT component. Adopted (matches the accepted `architecture.md` direction).

## Designer adjustments and additions (not in the draft)

- **A1 — Per-move persistence failure is an undefined user-visible flow.** With in-call commit (item 7), a legal move can fail at the storage layer. The session must remain at the pre-move state (the mutation is atomic: committed or not applied), but no interaction-design copy exists for "your move could not be saved" — the accepted 无法保存对局 flow covers only archive-and-clear. This goes to `interaction-design.md` **Need to discuss** and needs a product decision; the natural shape is: board unchanged, brief retryable error, game intact.
- **A2 — The result vocabulary lacks a value for ended-early records.** History records ended early carry "no competitive result", but `MxqGameState` has only the five fixture states; encoding ended-early as `ONGOING + ENDED_EARLY` on an immutable record is a trap for every frontend switch. Resolve jointly with the archive/schema draft: prefer one additional interface-level state for "no result" on archived records, while fixture files keep their five states untouched. Decide when the schema draft lands.
- **A3 — Contract text must state:** (a) the search callback must copy and return promptly — it runs on the engine thread and must not block or re-enter the core (only `mxq_status_*`/`mxq_blob_*` are legal inside it); (b) `mxq_store_history_page` returns records in the accepted pinned-first, newest-within-group order — ordering is a core guarantee, frontends never re-sort; (c) every accepted session mutation bumps `position_revision`, so an un-cancelled in-flight search is neutralized by staleness even if the frontend forgets to cancel — cancel is a promptness optimization, not a correctness requirement.
- **A4 — Fork-scope corrections for `engine-integration.md`:** (a) new confirmed patch trigger: `TranspositionTable::resize()` (and the Windows `aligned_large_pages_free`) call `exit()` on allocation failure, which the accepted error contract forbids crossing the boundary — recoverable Hash-allocation failure requires the fork change (`MXQ_ERR_ENGINE_HASH_ALLOC_FAILED` reserved now, unreachable until then); (b) the previously suspected NNUE `exit()` trigger is *removed* — the load state is externally observable (`Eval::eval_file_loaded`), so the core preflights the net and the engine-side `verify()` exit is unreachable; (c) Hash cadence: re-probe and re-prepare at each human-versus-AI game creation (fresh probe per the accepted policy; the low-memory retry flow already exists at game creation).
- **A5 — Documentation routing:** the full C surface (signatures, conventions, taxonomy, threading tables) becomes a new contract document `docs/core-interface.md`, referenced from `AGENTS.md`'s canonical list and the README; `architecture.md` keeps boundary-level statements plus two clarifying sentences resolving draft gaps G3 (the session carries the frozen game config; the *rules facade within it* is deterministic over position and history) and G4 ("plain value types" means presentation projections of the core-owned session).
- **A6 — Minor signature cleanups for the PR:** `MxqSearchRequest.movetime_ms` stays but is validated to equal the session's frozen value (self-describing diagnostics + drift check). `mxq_game_undo` keeps `out_plies_removed` (0/1/2 per the accepted decision-cycle rule).

## Open items carried to the user-decision batch

1. Per-move save-failure behavior (A1) — product decision.
2. Hash re-probe cadence recommendation (A4c) — stated as proposal; user can veto.
3. Everything from the archive/schema draft's own shortlist (format, extension, identity, pin-in-export, facing-kings, compatibility promise) — pending that draft.

Draft gaps G6/G7/G8/G10 remain open questions in the contracts; G1/G2 are folded into A4; G3/G4/G5 are resolved by items 3, 7, and A5 above.
